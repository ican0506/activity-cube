## 3. 完整主流程测试

### 流程一：管理员创建负责人账号

1. 管理员登录。
2. 进入“用户管理”。
3. 点击创建负责人账号。
4. 填写姓名、工号、初始密码、手机号、校区、部门/学院。
5. 保存后退出登录。
6. 使用新工号和初始密码登录。

预期结果：

- 负责人账号创建成功。
- 学生或负责人不能创建管理员和其他负责人账号。
- 操作日志中可看到创建负责人记录。

### 流程二：负责人创建活动

1. 负责人登录。
2. 进入“活动管理中心”。
3. 点击创建活动。
4. 填写基础信息、活动形式、活动类型、报名时间、活动时间、签到方式、签到时间和奖励设置。
5. 保存草稿。
6. 再次编辑后提交审核。

预期结果：

- 草稿活动学生端不可见。
- 提交后活动状态为待审核。
- 负责人只能管理自己创建的活动。

### 流程三：管理员审核活动

1. 管理员登录。
2. 进入“活动审核”。
3. 查看待审核活动详情。
4. 点击审核通过，或驳回并填写原因。

预期结果：

- 通过后活动进入已发布工作流。
- 学生端活动大厅可看到该活动。
- 驳回后负责人可看到驳回原因并重新提交。

### 流程四：学生报名

1. 学生登录。
2. 进入“活动大厅”。
3. 按校区或状态筛选活动。
4. 打开活动详情。
5. 点击立即报名。
6. 填写报名信息并提交。

预期结果：

- 报名成功。
- 活动卡片按钮变成“已报名”。
- 报名人数同步增加。
- 消息中心出现“报名成功”通知。
- 重复报名提示“你已报名，请勿重复提交”。

### 流程五：学生签到

线上活动：

1. 创建 `activityMode=online` 的活动。
2. 默认 `checkinMode=online`。
3. 学生报名后，在签到时间内进入详情页。
4. 点击“线上签到”。
5. 进入签到确认页后点击确认签到。

线下活动：

1. 创建 `activityMode=offline` 的活动。
2. 默认 `checkinMode=qr`。
3. 负责人进入二维码管理页。
4. 学生扫描签到二维码，或在 `/scan` 输入现场签到码。
5. 进入签到确认页后点击确认签到。

混合活动：

1. 创建 `activityMode=hybrid` 的活动。
2. 默认 `checkinMode=online`。
3. 学生可直接线上签到。
4. 如果负责人设置 `checkinMode=qr` 或 `both`，按对应规则测试扫码签到。

预期结果：

- 签到成功后状态变为“已签到”。
- 消息中心出现“签到成功”通知。
- 重复签到提示“你已完成签到，请勿重复签到”。

### 流程六：负责人查看名单和补签

1. 负责人进入活动管理中心。
2. 打开报名名单，查看报名学生。
3. 打开签到名单，查看签到记录。
4. 对已报名未签到学生进行人工补签，填写补签原因。
5. 导出报名名单、签到名单、未签到名单。

预期结果：

- 只有活动创建者或管理员可查看名单。
- 补签记录显示签到方式为“人工补签”。
- 未报名学生不能补签。
- 已签到学生不能重复补签。
- 导出 Excel 文件名包含活动名称和名单类型。

### 流程七：学生反馈

1. 活动发布后，学生进入活动详情。
2. 点击“反馈建议”。
3. 未结束前提交“活动建议”或“问题反馈”。
4. 学生签到后或活动结束后，提交“活动评价”并填写满意度评分。
5. 管理员或负责人进入反馈统计页。

预期结果：

- 建议和问题反馈不强制评分。
- 活动评价要求 1 到 5 分评分。
- 匿名反馈后台显示“匿名同学”。
- 后台能区分活动建议、问题反馈、活动评价，并显示平均评分。

### 流程八：活动统计和奖励

1. 负责人进入活动统计页。
2. 查看报名人数、签到人数、未签到人数、签到率。
3. 查看校区分布、报名签到转化和反馈统计。
4. 活动结束后，管理员或负责人发放活动奖励。
5. 学生进入个人中心查看活动成果。

预期结果：

- 统计数据与名单数量一致。
- 只有已签到学生可获得奖励。
- 同一活动同一学生不能重复发放奖励。
- 学生个人中心显示课外学时或积分。

## 4. 权限测试

学生不能访问：

- `/admin/**`
- 用户管理
- 活动审核
- 操作日志
- 名单导出
- 人工补签
- 活动二维码管理

负责人不能：

- 管理别人创建的活动
- 创建管理员账号
- 发布系统通知
- 查看全部操作日志
- 给别人活动补签或发放奖励

管理员可以：

- 管理所有活动
- 审核活动
- 管理用户
- 查看操作日志
- 发布系统通知
- 给任意活动发放奖励

## 5. 异常测试

| 场景 | 操作 | 预期提示 |
|---|---|---|
| 重复报名 | 同一学生重复报名同一活动 | 你已报名，请勿重复提交 |
| 人数已满 | 超过最大报名人数继续报名 | 该活动人数已满 |
| 未报名签到 | 未报名直接签到 | 你尚未报名，不能签到 |
| 重复签到 | 已签到后再次签到 | 你已完成签到，请勿重复签到 |
| 报名未开始 | 报名开始前报名 | 当前活动未开始报名 |
| 报名截止 | 报名结束后报名 | 当前活动报名已结束 |
| 签到未开始 | 签到开始前签到 | 签到尚未开始 |
| 签到已结束 | 签到结束后签到 | 签到已结束 |
| 活动取消 | 取消后报名或签到 | 当前活动已取消 |
| 二维码无效 | 修改 code 后扫码 | 签到二维码无效 |
| 签到码无效 | 输入错误签到码 | 签到码无效 |
| 登录过期 | 删除 token 后访问接口 | 跳转登录页 |
| 无权限访问 | 学生访问后台接口 | 无权限 |

## 6. 手机扫码测试

1. 电脑和手机连接同一 Wi-Fi。
2. 前端启动使用：`npm run dev -- --host 0.0.0.0`。
3. `frontend/.env.development` 配置为电脑 IP 后端地址。
4. 手机打开 `http://电脑IP:5173`。
5. 用学生账号登录。
6. 扫描报名二维码或签到二维码。
7. 摄像头无法启动时，粘贴二维码链接或输入现场签到码。

注意：手机浏览器在 HTTP 局域网环境下可能限制摄像头，这属于浏览器安全策略，可用备用方式完成测试。
