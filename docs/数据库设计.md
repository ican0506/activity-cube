# 活动魔方数据库设计

默认数据库名：`activity_cube`。

全新数据库初始化脚本：

```text
sql/activity_cube_final.sql
```

已有数据库升级补丁：

```text
docs/sql/*.sql
```

## 1. user 用户表

作用：保存学生、活动负责人、管理员账号。

核心字段：

- `id`：用户 ID。
- `username`：登录账号。学生默认等于学号，负责人默认等于工号。
- `password`：BCrypt 加密后的密码。
- `real_name`：真实姓名。
- `student_no`：学生学号。
- `work_no`：负责人工号。
- `grade_year`、`major_code`、`major_name`：学生年级和专业信息。
- `role`：`student`、`organizer`、`admin`。
- `campus`：龙子湖校区、文化路校区、许昌校区。
- `college`、`class_name`、`phone`、`avatar_url`、`bio`：资料信息。
- `status`：账号启用状态。

关键约束：

- `username` 唯一。
- `student_no` 唯一。
- `work_no` 唯一。
- 公开注册只能创建学生账号。

## 2. activity 活动表

作用：保存活动基础信息、审核状态、时间、签到方式、奖励配置。

核心字段：

- `id`：活动 ID。
- `title`、`description`：活动名称和说明。
- `cover_url`：活动封面。
- `activity_mode`：活动形式，`online` 线上、`offline` 线下、`hybrid` 混合。
- `checkin_mode`：签到方式，`online` 线上签到、`qr` 现场扫码、`both` 两种都支持。
- `activity_category`：活动类型，例如公益活动、讲座培训、文体活动等。
- `campus`：活动范围，全校区、龙子湖校区、文化路校区、许昌校区、线上。
- `location`：活动地点，线上活动可填写会议链接或“线上活动”。
- `register_start_time`、`register_end_time`：报名时间。
- `start_time`、`end_time`：活动时间。
- `checkin_start_time`、`checkin_end_time`：签到时间。
- `max_participants`：人数上限。
- `allow_cross_campus`：是否允许跨校区报名。
- `reward_enabled`、`reward_type`、`reward_hours`、`reward_points`、`reward_description`：奖励设置。
- `status`：工作流状态，草稿、待审核、已驳回、已发布、已取消。
- `creator_id`：创建人。

关键说明：

- 活动形式 `activity_mode` 和签到方式 `checkin_mode` 分开，不能混用。
- 活动类型 `activity_category` 与线上线下不是一个概念。
- 草稿和已取消是手动工作流状态；报名中、进行中、已结束等展示状态由后端按时间计算。

## 3. registration 报名表

作用：保存学生报名记录。

核心字段：

- `activity_id`：活动 ID。
- `user_id`：学生用户 ID。
- `name`、`student_no`、`college`、`major_class`、`phone`、`campus`：报名信息。
- `remark`：报名备注。
- `create_time`、`update_time`：创建和更新时间。

关键约束：

- 同一活动同一用户只能报名一次。
- 同一活动同一学号只能报名一次。
- 报名人数不能超过活动人数上限。

## 4. checkin 签到表

作用：保存线上签到、扫码签到、人工补签记录。

核心字段：

- `activity_id`：活动 ID。
- `user_id`：签到学生 ID。
- `registration_id`：报名记录 ID。
- `checkin_time`：签到时间。
- `checkin_type`：`online`、`qr`、`manual`。
- `operator_id`、`operator_name`：人工补签操作人。
- `remark`：补签原因。

关键约束：

- 同一活动同一学生只能签到一次。
- 未报名不能签到。
- 人工补签必须记录操作人和原因。

## 5. feedback 反馈表

作用：保存活动建议、问题反馈和满意度评价。

核心字段：

- `activity_id`：活动 ID。
- `user_id`：反馈学生 ID。
- `feedback_type`：`suggestion` 活动建议、`issue` 问题反馈、`evaluation` 活动评价。
- `score`：满意度评分，仅活动评价必填。
- `content`：反馈内容。
- `suggestion`：改进建议。
- `handle_status`：处理状态，未处理、已查看、已处理。
- `anonymous`：是否匿名。

关键说明：

- 活动发布后可提交建议和问题反馈。
- 学生签到后或活动结束后可提交活动评价。
- 匿名反馈在后台显示为“匿名同学”。

## 6. activity_media 活动媒体表

作用：保存活动封面、宣传图片、视频信息。

核心字段：

- `activity_id`：活动 ID。
- `media_type`：`image` 或 `video`。
- `usage_type`：`cover`、`gallery`、`video`。
- `url`：文件访问 URL。
- `file_name`、`original_name`、`size`：文件信息。
- `sort_order`：排序。

说明：MySQL 只保存 URL 和文件信息，不保存二进制文件。

## 7. feedback_media 反馈媒体表

作用：保存反馈附件图片和视频。

核心字段：

- `feedback_id`：反馈 ID。
- `activity_id`：活动 ID。
- `user_id`：上传学生 ID。
- `media_type`：图片或视频。
- `url`、`file_name`、`original_name`、`size`：文件信息。

关系：

- 多条附件属于一条反馈。

## 8. notice 通知表

作用：保存通知主体。

核心字段：

- `activity_id`：关联活动，可为空。
- `sender_id`、`sender_name`：发送人。
- `title`、`content`：通知标题和内容。
- `notice_type`：通知类型，例如报名成功、签到成功、活动提醒、系统通知。
- `target_type`：通知对象范围。
- `biz_key`：业务幂等键，避免重复提醒。

## 9. notice_receiver 通知接收表

作用：保存通知接收人和已读状态。

核心字段：

- `notice_id`：通知 ID。
- `receiver_id`：接收用户 ID。
- `read_status`：未读或已读。
- `read_time`：阅读时间。

关键约束：

- 同一通知同一接收人只能生成一条接收记录。

## 10. operation_log 操作日志表

作用：记录管理员和负责人的关键操作。

核心字段：

- `user_id`、`username`、`role`：操作人信息。
- `operation`：操作类型。
- `target_type`、`target_id`：操作对象。
- `detail`：操作详情。
- `ip`：操作 IP。
- `create_time`：操作时间。

记录场景：

- 创建负责人账号。
- 审核活动。
- 取消活动。
- 人工补签。
- 刷新签到二维码。
- 导出名单。
- 发放奖励。

## 11. student_activity_reward 活动成果/奖励表

作用：保存学生参加活动后获得的课外学时、积分或奖励说明。

核心字段：

- `activity_id`：活动 ID。
- `student_id`、`student_no`：学生。
- `activity_category`：活动类型。
- `reward_type`：奖励类型。
- `reward_hours`：课外学时。
- `reward_points`：积分。
- `reward_description`：奖励说明。
- `issued_by`、`issued_by_name`：发放人。
- `issued_time`：发放时间。
- `status`：奖励状态。

关键约束：

- 同一活动同一学生不能重复发放奖励。
- 只有已报名且已签到的学生才能获得奖励。

## 12. lottery_result 抽奖结果表

作用：保存随机抽奖历史结果。

核心字段：

- `activity_id`：活动 ID。
- `user_id`、`registration_id`：中奖学生和报名记录。
- `real_name`、`student_no`、`college`、`class_name`、`phone`、`campus`：结果快照。
- `source`：抽奖来源，报名名单或签到名单。
- `round_no`：抽奖轮次。

## 13. 主要关系

- `user` 1 对多 `activity`：负责人创建活动。
- `activity` 1 对多 `registration`：活动报名名单。
- `activity` 1 对多 `checkin`：活动签到名单。
- `activity` 1 对多 `feedback`：活动反馈。
- `activity` 1 对多 `notice`：活动通知。
- `notice` 1 对多 `notice_receiver`：通知接收人。
- `activity` 1 对多 `student_activity_reward`：活动奖励记录。
- `feedback` 1 对多 `feedback_media`：反馈附件。
