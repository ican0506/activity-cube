# 活动魔方 VibeCoding 过程记录

## 1. 记录目的

本文件用于说明“活动魔方 activity-cube”项目在开发过程中使用 AI 辅助编码、需求迭代、Bug 排查和文档整理的过程。该记录可作为 VibeCoding 比赛材料，证明项目不是只提交最终代码，而是在 AI 协作下逐步完成产品设计、工程实现和交付整理。

## 2. AI 协作方式

本项目采用“人提出需求，AI 分析并修改代码，人运行验证，再继续迭代”的协作模式。

协作流程：

```text
提出业务需求
→ AI 阅读现有代码
→ AI 给出实现边界
→ AI 修改前端/后端/SQL/文档
→ 本地运行前后端
→ 根据截图或报错继续修复
→ 形成可运行版本
→ 整理最终交付材料
```

## 3. 提示词迭代过程

### 阶段一：项目骨架与数据库

目标：

- 根据“活动魔方：校园活动组织一站式轻工具平台”需求生成项目骨架。
- 建立 Spring Boot 后端、Vue 3 前端、MySQL 数据库脚本。

代表性提示词：

```text
请严格按照 Markdown 文档生成项目，先生成项目骨架、数据库 SQL、后端 Spring Boot 基础代码和前端 Vue 3 基础页面。不要一次性做所有高级功能，先完成 MVP 闭环。
```

AI 输出内容：

- 后端基础包结构。
- 前端基础页面。
- `activity_cube` 数据库初始化脚本。
- 登录、活动列表、报名、签到等 MVP 功能。

### 阶段二：登录、注册和权限

目标：

- 增加前后端分离登录页。
- 修复 401、403、token 携带、登录回跳。
- 限制公开注册只能注册学生账号。

代表性提示词：

```text
请帮我修复登录接口请求和权限拦截问题。登录接口不要错误请求到 localhost:5173，登录成功后保存 token，每次请求自动携带 token，401 时跳转登录页。
```

AI 输出内容：

- Axios 请求封装。
- token 保存和请求头携带。
- 路由守卫。
- 学生、负责人、管理员导航区分。

### 阶段三：活动业务逻辑

目标：

- 活动状态自动计算。
- 报名时间、签到时间限制。
- 活动审核机制。
- 学生取消报名。

代表性提示词：

```text
我发现活动状态目前需要手动选择，这不合理。请改成活动状态自动计算，只有报名中可以报名，签到根据签到开始时间和签到结束时间限制。
```

AI 输出内容：

- 活动状态工具类。
- 报名和签到限制。
- 活动审核接口和页面。
- 操作日志设计。

### 阶段四：二维码报名和签到

目标：

- 支持报名二维码和签到二维码。
- 支持扫码落地页。
- 支持未登录扫码后登录回跳。
- 手机摄像头不可用时支持备用方案。

代表性提示词：

```text
请优化扫码报名和扫码签到逻辑。新增 /scan/resolve 扫码落地页，二维码不能写死 localhost，使用 window.location.origin。
```

AI 输出内容：

- `/scan` 扫码页面。
- `/scan/resolve` 落地页。
- 签到码解析接口。
- 二维码管理页面。

### 阶段五：名单导出、抽奖分组和反馈统计

目标：

- 前端 xlsx 导出报名名单、签到名单、未签到名单。
- 增加随机抽奖和随机分组。
- 增加活动反馈和满意度统计。

代表性提示词：

```text
请继续新增 Excel 导出功能，优先使用前端 xlsx 实现导出。支持报名名单、签到名单、未签到名单。
```

AI 输出内容：

- Excel 导出工具。
- 抽奖接口和抽奖页面。
- 随机分组工具页。
- 反馈表单和反馈统计页。

### 阶段六：图片视频上传和消息中心

目标：

- 活动封面、活动图片视频上传。
- 反馈附件上传。
- 消息中心和通知发布。

代表性提示词：

```text
请新增图片和视频上传功能，不要把二进制内容存入 MySQL，只保存文件访问 URL 和文件信息。
```

AI 输出内容：

- 文件上传接口。
- 静态资源映射。
- 活动媒体表。
- 反馈媒体表。
- 消息中心、活动通知和系统通知。

### 阶段七：产品逻辑优化

目标：

- 线上、线下、混合活动区分。
- 活动形式和签到方式分开。
- 活动反馈支持建议、问题和评价三类。
- 个人中心展示活动成果。

代表性提示词：

```text
线上线下混合活动不应该强制线下扫码签到，活动形式和签到方式需要分开，不要混用。
```

AI 输出内容：

- `activityMode` 和 `checkinMode` 分离。
- 混合活动默认线上签到。
- 反馈类型 `suggestion`、`issue`、`evaluation`。
- 后台反馈统计按类型展示。

### 阶段八：UI 视觉迭代

目标：

- 从普通后台模板优化为校园轻工具平台。
- 删除大面积绿色 Banner。
- 保留河南农业大学绿色风格。
- 适配电脑端和手机端。

代表性提示词：

```text
请重新设计活动魔方前端页面，删除所有大面积绿色 Banner，采用白色背景 + 绿色强调色，页面重点突出功能和数据。
```

AI 输出内容：

- 活动大厅卡片化。
- 顶部头像菜单。
- 扫一扫相机按钮。
- 个人中心和我的活动页面结构优化。

### 阶段九：最终交付整理

目标：

- 完善 README。
- 整理测试说明、数据库设计、接口文档。
- 准备比赛交付包结构。

代表性提示词：

```text
请帮我整理 activity-cube 项目的最终交付材料和测试说明，老师或评委拿到项目后能初始化数据库、启动前后端、使用测试账号完整跑通主流程。
```

AI 输出内容：

- README。
- 测试说明。
- 数据库设计。
- 接口文档。
- 项目说明文档。
- VibeCoding 过程记录。
- 桌面比赛交付目录。

## 5. AI 辅助开发证明点

本项目可从以下材料证明 AI 参与开发：

- 多轮自然语言需求提示词。
- AI 根据现有代码进行增量修改。
- AI 生成 SQL 补丁和最终初始化 SQL。
- AI 根据浏览器截图定位前端问题。
- AI 修复后运行 `npm run build`、`mvn test` 等验证命令。
- AI 生成 README、测试说明、接口文档和项目说明。

## 6. 人工参与说明

开发者主要负责：

- 确定项目选题和校园活动业务场景。
- 提供需求文档和截图反馈。
- 在 IDEA、Navicat、浏览器中运行和验证。
- 判断产品逻辑是否符合真实校园管理场景。
- 按比赛要求整理最终材料。

AI 主要负责：

- 代码实现建议和直接代码修改。
- SQL 设计和补丁生成。
- 前端 UI 结构优化。
- 后端业务逻辑补全。
- Bug 定位和修复。
- 文档整理和测试流程编写。
