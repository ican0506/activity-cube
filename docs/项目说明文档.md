# 活动魔方 activity-cube 项目说明文档

## 1. 项目名称

活动魔方 activity-cube

## 2. 产品定位

活动魔方是面向高校校园活动组织场景的一站式轻工具平台。系统定位不是替代第二课堂、教务系统或学校统一认证平台，而是聚焦活动组织过程中的高频问题：

- 活动负责人发布活动效率低。
- 报名名单收集分散。
- 现场签到容易拥堵或漏签。
- 活动通知触达不集中。
- 活动结束后缺少反馈和复盘数据。
- 学生活动成果难以沉淀。

活动魔方通过“活动创建、审核、报名、签到、反馈、统计、成果记录”的完整流程，帮助学生、负责人和管理员更轻量地完成校园活动管理。

## 3. 目标用户

### 学生

- 浏览校园活动。
- 报名活动。
- 线上签到或现场扫码签到。
- 查看消息通知。
- 提交活动建议、问题反馈和满意度评价。
- 查看个人活动成果、课外学时和积分。

### 活动负责人

- 创建和管理自己负责的活动。
- 生成报名二维码和签到二维码。
- 查看报名名单和签到名单。
- 为学生人工补签。
- 发布活动通知。
- 查看活动统计和反馈统计。
- 发放活动奖励。

### 系统管理员

- 审核活动。
- 管理所有活动。
- 创建负责人账号。
- 管理用户状态和角色。
- 发布系统通知。
- 查看操作日志和数据总览。

## 4. 核心功能说明

### 活动管理

- 活动创建、编辑、提交审核。
- 管理员审核通过或驳回。
- 活动状态按时间自动计算。
- 支持草稿、待审核、已驳回、已发布、已取消等工作流状态。

### 活动形式与签到方式

活动形式：

- 线上活动 `online`
- 线下活动 `offline`
- 混合活动 `hybrid`

签到方式：

- 线上签到 `online`
- 现场扫码签到 `qr`
- 两种都支持 `both`

说明：活动形式和签到方式分开设计。混合活动默认允许线上签到，不强制现场扫码。

### 报名功能

- 学生在报名时间内报名。
- 同一活动同一学生不能重复报名。
- 支持人数上限。
- 报名成功后自动生成消息通知。

### 二维码和扫码

- 报名二维码跳转扫码落地页。
- 签到二维码携带活动 ID 和签到码。
- 扫码落地页支持未登录回跳。
- 手机摄像头不可用时，支持粘贴二维码链接或输入现场签到码。

### 签到和人工补签

- 已报名学生可在签到时间内签到。
- 线上活动默认线上签到。
- 线下活动默认现场扫码签到。
- 管理员或活动负责人可为已报名未签到学生人工补签。
- 补签记录保存操作人、补签原因和补签时间。

### 反馈和满意度统计

反馈类型：

- 活动建议 `suggestion`
- 问题反馈 `issue`
- 活动评价 `evaluation`

活动发布后即可提交建议和问题反馈。学生签到后或活动结束后，可以提交满意度评价。后台统计建议数量、问题数量、评价数量和平均评分。

### 消息中心

- 报名成功通知。
- 签到成功通知。
- 活动开始提醒。
- 签到提醒。
- 反馈提醒。
- 负责人活动通知。
- 管理员系统通知。

### 活动成果

- 活动结束后，负责人或管理员可给已签到学生发放课外学时、积分或奖励说明。
- 学生个人中心展示活动成果。
- 同一活动同一学生不能重复发放奖励。

### 数据统计

- 报名人数。
- 签到人数。
- 未签到人数。
- 签到率。
- 校区分布。
- 反馈数量和评分分布。

## 5. 技术方案

### 前端技术栈

- Vue 3：页面组件开发。
- Vite：前端构建和本地开发服务。
- Element Plus：表单、表格、弹窗、消息提示等基础组件。
- Vue Router：前端路由和权限跳转。
- Pinia：用户登录状态管理。
- Axios：接口请求封装。
- ECharts：统计图表。
- qrcode：生成二维码。
- html5-qrcode：手机摄像头扫码。
- xlsx：前端导出 Excel。

### 后端技术栈

- Spring Boot：后端接口服务。
- MyBatis Plus：数据库 ORM。
- MySQL：业务数据存储。
- Maven：依赖管理和测试。
- BCrypt：密码加密。
- Flyway：数据库迁移能力预留。

### 数据库设计

核心表：

- `user`
- `activity`
- `registration`
- `checkin`
- `feedback`
- `notice`
- `notice_receiver`
- `operation_log`
- `student_activity_reward`
- `activity_media`
- `feedback_media`
- `lottery_result`

数据库通过唯一约束保证：

- 用户名唯一。
- 学号唯一。
- 工号唯一。
- 同一活动同一学生只能报名一次。
- 同一活动同一学生只能签到一次。
- 同一活动同一学生只能发放一次奖励。

## 6. 权限设计

### student 学生

- 浏览活动。
- 报名。
- 签到。
- 提交反馈。
- 查看自己的报名、签到、消息和活动成果。

### organizer 活动负责人

- 创建活动。
- 管理自己创建的活动。
- 查看自己活动的名单、统计、反馈。
- 发布自己活动的通知。
- 为自己活动人工补签。

### admin 管理员

- 管理所有活动。
- 审核活动。
- 管理用户。
- 创建负责人账号。
- 查看操作日志。
- 发布系统通知。

## 7. AI 工具使用说明

本项目开发过程中使用 AI 辅助完成需求分析、代码生成、Bug 排查、UI 优化、数据库设计和文档整理。AI 主要参与以下工作：

- 根据需求文档生成项目骨架。
- 设计 MySQL 表结构和 SQL 补丁。
- 生成 Spring Boot Controller、Service、Entity、Mapper 基础代码。
- 生成 Vue 3 页面、路由和 API 封装。
- 优化登录、权限、扫码、签到、反馈等产品逻辑。
- 修复接口请求、字段缺失、空值白屏、权限拦截等问题。
- 生成 README、测试说明、数据库设计、接口文档等交付材料。

AI 并非一次性生成完整系统，而是采用“需求拆解、逐步实现、人工验证、继续迭代”的方式辅助开发。开发者负责：

- 提出业务需求和场景。
- 检查运行效果。
- 执行数据库脚本。
- 验证前后端功能。
- 决定最终产品逻辑。

## 8. 项目亮点

- 支持学生、负责人、管理员三类角色。
- 活动审核机制贴近真实校园活动管理。
- 活动形式与签到方式分离，适配线上、线下、混合活动。
- 支持二维码报名和扫码签到。
- 摄像头不可用时提供备用签到码方案。
- 支持人工补签和操作日志。
- 支持消息通知和未读状态。
- 支持活动反馈、满意度统计和附件上传。
- 支持课外学时、积分等活动成果沉淀。
- 前后端分离，便于部署和展示。
